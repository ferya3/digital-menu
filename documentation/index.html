Overview

MenuPilot is a self-hosted digital menu platform. Guests scan a QR code on the table, browse the menu, order, call the waiter and pay — without installing an app. Each venue manages everything from its own dashboard. In SaaS mode you sell subscriptions: venues sign up on your website and get their own subdomain, menu, dashboard and isolated data.

AddressWhat it is

Without a root domain the app runs in single-restaurant mode: one menu on your domain and one dashboard at /staff.

Requirements

  • A clean Ubuntu 22.04 or 24.04 server (VPS) with root or sudo access — 1 GB RAM minimum, 2 GB recommended.
  • A domain name. For SaaS mode you need DNS access to add a wildcard record.
  • Optional: a Stripe account for online payments and a Twilio account for SMS.

The installer installs Node.js 22, Nginx, ffmpeg, pm2 and Certbot automatically and creates a swap file on small servers.

DNS setup

At your DNS provider, point these A records to your server IP (and AAAA records if your server has IPv6):

NameTypeValue
@ (yourdomain.com)Ayour server IP
wwwAyour server IP
* (all subdomains — SaaS mode)Ayour server IP

If you use Cloudflare, set these records to DNS only (grey cloud) so Let's Encrypt can issue certificates for each venue subdomain.

Installation

1. Upload the files

Upload the contents of the menupilot folder (the one containing install.sh) to your server, e.g. /opt/menupilot:

scp -r menupilot root@YOUR-SERVER-IP:/opt/menupilot

2a. Install in SaaS mode

cd /opt/menupilot
sudo ROOT_DOMAIN=yourdomain.com EMAIL=you@yourdomain.com PLATFORM_ADMIN_PASSWORD='a-strong-password' bash install.sh

2b. Or install for a single restaurant

cd /opt/menupilot
sudo DOMAIN=myrestaurant.com EMAIL=you@myrestaurant.com ADMIN_PASSWORD='a-strong-password' bash install.sh

Without DOMAIN the site runs on the server IP over HTTP; connect a domain later with sudo DOMAIN=myrestaurant.com bash set-domain.sh. To switch an existing single-restaurant install to SaaS mode later, run sudo ROOT_DOMAIN=yourdomain.com EMAIL=… PLATFORM_ADMIN_PASSWORD=… bash set-saas.sh.

When the installer finishes it prints the addresses and passwords. If you did not pass a password, a random one is generated and printed — keep it safe.

First steps (SaaS mode)

  1. Open https://yourdomain.com/admin and sign in.
  2. Settings: trial days, open/close signups, plans and prices, currency, Stripe secret key, bank-transfer details, Twilio.
  3. Site content → Brand & SEO: brand name, logo, color, SEO title and description (with a live Google preview), Google Search Console verification code.
  4. Site content → Hero → Create demo menu, save, then open Venues → demo → Enter dashboard and replace the sample items with real photos. Visitors see a “Try the live demo menu” button and a QR code.
  5. Edit the rest of the site: feature cards (with photos), display modes, steps, pricing texts, FAQ, testimonials (real ones only), footer and contact (enables the floating WhatsApp/call button), legal pages.
  6. Review the Articles and City pages sections and publish your own content regularly.

Guest menu

The table QR code opens https://venue.yourdomain.com/?table=4. Guests choose between carousel, grid and list view, add items with notes, order, follow the order status, call the waiter, request the bill and pay. Opening the menu without a table number shows a “scan the QR code on your table” screen with an in-browser QR scanner and a browse-only mode.

Stripe payments

Subscriptions (your Stripe account)

  1. Get your secret key at dashboard.stripe.com/apikeys (use sk_test_… first).
  2. Admin → Settings → Stripe: paste the key and save; set the currency (e.g. USD).
  3. Optional webhook: https://yourdomain.com/stripe/webhook, event checkout.session.completed. Payments are also confirmed when the customer returns from Stripe; the webhook covers customers who close the tab.

Table bills (each venue's own Stripe account)

In the venue dashboard → Settings → Payments, enable Stripe and paste the venue's secret key. Guests then see “Pay online with card”. Optional webhook: https://venue-domain/stripe/webhook. Payments are recorded in accounting as “Online (card)”.

Payments are never trusted from the browser: the app always fetches the Checkout Session from Stripe and checks amount and currency before marking anything as paid.

Twilio SMS

Used for guest phone verification, bulk SMS (venues), signup verification and renewal reminders (platform). In the settings choose Twilio and enter the Account SID, Auth Token and the sender (a Twilio number in E.164 format like +15551234567, an alphanumeric sender ID where supported, or a Messaging Service SID starting with MG). Use “Send test SMS” to check. Without SMS the app works in demo mode (verification codes are shown on screen).

Phone numbers are stored in international E.164 format. Set DEFAULT_COUNTRY_CODE (e.g. 1) so guests can type local numbers.

Partner program

Admin → Partners → New partner: name, code (used in the link), commission percent and whether it applies to the first payment only or to all payments. Share https://yourdomain.com/r/CODE; visitors are attributed for 60 days, or they can enter the code in the signup form. Each partner gets a private report page (link in the admin panel). Record payouts to keep the balance up to date.

Live demo mode

Want to run a public demo of your platform (for example to show it to restaurant owners)? Demo mode keeps everything a visitor needs working — ordering, Stripe test payments, the kitchen flow, browsing every panel and entering venue dashboards — while settings, passwords, keys, deleting, uploads, site content, SMS and signups are disabled. Both panels show a demo banner and the login screens show the demo passwords.

# 1) turn demo mode on (use the same passwords for the super admin and the demo venue)
sudo DEMO_ADMIN_PASSWORD='DemoAdmin2026!' DEMO_STAFF_PASSWORD='Demo1234!' bash demo-reset.sh enable
# 2) prepare the demo (demo venue, photos, a few orders) — then save it as the baseline
sudo bash demo-reset.sh save
# 3) reset the data to the baseline every 3 hours
sudo bash demo-reset.sh cron 3
# reset now: sudo bash demo-reset.sh restore · turn off: sudo bash demo-reset.sh disable

Tip: prepare the demo data (step 2) before enabling demo mode, or temporarily disable it while you edit — in demo mode the admin panel is read-only.

Security

  • No default passwords; weak passwords must be changed on first sign-in; scrypt hashing.
  • Login lock-out after repeated failures; rate limits for orders, requests, receipts, SMS codes — stored on disk.
  • Strict Content-Security-Policy with per-request nonces, HSTS, X-Frame-Options and more, set by the app itself.
  • Secrets (Stripe/Twilio keys, signing keys, password hashes) encrypted at rest with AES-256-GCM; secrets are masked in the panels.
  • Each venue has its own database, uploads folder, session signing key and live channel.

Customization

  • Brand, colors (10 presets), texts and images: from the admin panel — no code needed.
  • Sample menus for new venues: lib/seeds.ts and lib/data.ts. Default website texts: lib/site-content.ts. Topic pages: lib/solutions.ts. Seed articles: lib/article-seeds.ts. Seed cities: lib/cities.ts.
  • Theme tokens: app/globals.css. After code changes run sudo bash update.sh.

Troubleshooting

ProblemSolution
A new venue subdomain shows a certificate warningCheck the wildcard * DNS record (DNS only, not proxied) and see /var/log/cafe-certs.log.
“Internal Server Error”pm2 logs cafe shows the reason; make sure the server has Node.js 22 (node -v).
Stripe payment stays “being confirmed”Check the secret key and currency; add the webhook URL so late payments are confirmed.
SMS not deliveredUse “Send test SMS”; check the Twilio logs, the sender and that the destination country is enabled in Twilio's geo permissions.
Forgot the super-admin passwordsudo PLATFORM_ADMIN_PASSWORD='new-password' bash reset-admin-password.sh
