# کافه آرتاویل — نسخهٔ React

بازنویسی منوی دیجیتال کافه با **React + TypeScript + Tailwind + shadcn/ui**.

تجربهٔ کاملِ **مشتری و کارکنان** (فاز ۱ تا ۴):
- **مشتری** (`/?table=1`): منو با سه حالت نمایش، دارک‌مود، سبد خرید، RTL؛ وصل به بک‌اندِ واقعی —
  منو از سرور، ثبتِ سفارشِ واقعی، **صورتحساب = جمعِ همهٔ سفارش‌های پرداخت‌نشده**،
  **وضعیت سفارشِ لحظه‌ای** (Socket.IO)، و دکمهٔ درخواست (گارسون/فاکتور).
- **کارکنان** (`/staff`): ورود با رمز، مدیریتِ زندهٔ سفارش‌ها (آشپزخانه + صندوق) و درخواست‌ها.

## اجرا (دو حالت)

نیاز: Node.js 18 یا بالاتر.

### حالت ۱ — فقط رابط کاربری (نمایشی، بدون سرور)

```bash
npm install
npm run dev        # → http://localhost:5173
```

اگر سرور Node در دسترس نباشد، اپ خودکار به دادهٔ نمونهٔ محلی می‌افتد و بالای صفحه
«حالت نمایشی» نشان داده می‌شود. سه حالت نمایش و سبد خرید کار می‌کنند ولی ثبت سفارش/صورتحساب
نیاز به سرور دارد.

### حالت ۲ — با بک‌اندِ واقعی (ثبت سفارش و صورتحساب کار می‌کند)

بک‌اند همان پروژهٔ Node قبلی توست (پوشهٔ cafe). در یک ترمینال:

```bash
cd cafe && npm install && npm start      # سرور روی http://localhost:3000
```

در ترمینال دوم، این پروژهٔ React را اجرا کن:

```bash
npm install
npm run dev        # مشتری: http://localhost:5173/?table=1
                   # کارکنان: http://localhost:5173/staff   (رمز پیش‌فرض: cafe1234)
```

Vite به‌صورت خودکار درخواست‌های `/api`، `/images` و `/socket.io` را به سرور Node
(روی پورت 3000) پراکسی می‌کند. برای وصل‌شدن به سروری روی آدرس دیگر:

```bash
BACKEND=https://artavilstar.com npm run dev     # در حالت توسعه
# یا برای build نهایی:
VITE_API_URL=https://artavilstar.com npm run build
```

### خروجی نهایی (build)

```bash
npm run build      # خروجی در dist/
npm run preview
```

> `?table=1` در آدرس، شمارهٔ میز را تعیین می‌کند (مثل نسخهٔ قبلی، از روی QR هر میز).

## چی ساخته شده (فاز ۱)

- **سه حالت نمایش منو** با دکمهٔ سوییچ بالای صفحه:
  - **کاروسل** — کاورفلوی سه‌بعدی (همان کامپوننتی که فرستادی، با لهجهٔ طلایی و پس‌زمینهٔ تیره).
  - **شبکه‌ای** — کارت‌های محصول با عکس، تگ، قیمت و دکمهٔ افزودن.
  - **لیستی** — ردیف‌های بازشونده با فلشِ بالا/پایینِ انیمیشن‌دار (اشاره به لمس برای باز شدن).
- **دارک‌مود** با پالت گرم و ذخیرهٔ انتخاب کاربر.
- **سبد خرید**: شمارنده روی هدر، نوار پایینِ جمعِ سفارش، و کشوی سبد با استپر تعداد و جمع کل.
- **دسته‌بندی‌ها**: همه / قهوه‌های گرم / سرد / کیک و دسر.
- اعداد و قیمت‌ها به‌صورت فارسی و با واحد «تومان».
- واترمارک بسیار کم‌رنگِ نام کافه روی عکس محصول.
- چیدمان کاملاً RTL و فونت وزیرمتن.

## ساختار فایل‌ها

```
src/
  Root.tsx                        مسیریابیِ سبک: /staff → پنل کارکنان، وگرنه اپِ مشتری
  App.tsx                         اپِ مشتری (منو، سه حالت نمایش، سبد، صورتحساب، وضعیت، درخواست)
  StaffApp.tsx                    پنل کارکنان (ورود، سفارش‌ها/صندوق، درخواست‌ها، زنده)
  ManageMenu.tsx                  مدیریت منو (محصولات، دسته‌ها، کدهای QR)
  api.ts                          کلاینتِ API بک‌اند (منو، سفارش، صورتحساب، رسید، درخواست، ورود، مدیریت منو) + fallback محلی
  socket.ts                       اتصال Socket.IO (مشتری و کارکنان) + برچسب‌های فارسیِ وضعیت
  data.ts                         داده‌های نمونه (وقتی سرور در دسترس نیست)
  index.css                       تم shadcn با رنگ اصلیِ قرمزِ کافه + دارک‌مود
  lib/utils.ts                    تابع cn (ترکیب کلاس‌ها)
  components/ui/
    button.tsx                    دکمهٔ shadcn
    3-d-coverflow-carousel.tsx    کامپوننت کاورفلوی سه‌بعدی
```

## نقشهٔ راه

- ✅ **فاز ۱** — رابط مشتری: سه حالت نمایش (کاروسل سه‌بعدی/شبکه‌ای/لیستی)، دارک‌مود، سبد خرید، RTL.
- ✅ **فاز ۲** — اتصال به بک‌اند: منو از سرور، ثبت واقعی سفارش، و صورتحساب میز با **جمعِ همهٔ سفارش‌های پرداخت‌نشده** و نمایش تک‌تک فاکتورها + ارسال رسید پرداخت.
- ✅ **فاز ۳** — **وضعیت سفارش لحظه‌ای (Socket.IO)**: مشتری بدون رفرش می‌بیند سفارشش «در حال آماده‌سازی» یا «آماده» شد؛ نوار پیشرفتِ زنده، اعلانِ تأیید/رد پرداخت، و پیگیریِ سفارش که با رفرشِ صفحه هم حفظ می‌شود.
- ✅ **فاز ۴** — **پنل کارکنان با React** روی مسیر `/staff`: ورود با رمز، تبِ **سفارش‌ها** (کنترل وضعیتِ آشپزخانه: تأیید→آماده‌سازی→آماده→سرو + لغو) و **صندوق** (دیدن فیش پرداخت، تأیید/رد با حذفِ عکسِ فیش، هشدارِ فیشِ تکراری)، و تبِ جدا‌گانهٔ **درخواست‌ها** (گارسون/فاکتور با مبلغ). همه‌چیز زنده به‌روزرسانی می‌شود؛ سفارش/درخواستِ جدید بی‌درنگ روی پنل ظاهر می‌شود. سمتِ مشتری هم دکمهٔ **درخواست** (صدا زدن گارسون / درخواست فاکتور) اضافه شد.
- ✅ **فاز ۵** — **مدیریت منو با React** (تبِ «مدیریت منو» در پنل کارکنان):
  - **محصولات**: افزودن/ویرایش/حذف با فرم کامل (نام، دسته، قیمت، قیمتِ قبل از تخفیف، توضیحات، ایموجی یا **آپلود عکس**، موجود/ناموجود) و فیلتر بر اساس دسته.
  - **دسته‌ها**: افزودن/ویرایش/حذف با **ایموجی یا عکسِ اختیاریِ آپلودی** برای هر دسته.
  - **کدهای QR**: تولیدِ QRِ هر میز (بازهٔ دلخواه) با لینکِ منو و دکمهٔ **چاپ**.
  - تغییرِ منو **زنده** روی اپِ مشتری هم اعمال می‌شود (رویدادِ `menu:updated`).

> **همهٔ ۵ فاز کامل شد — کلِ اپ (مشتری + کارکنان + مدیریت) در React است.**
> **دسترسی:** `/?table=۱` برای مشتری و `/staff` برای کارکنان. رمزِ پیش‌فرض `cafe1234`.
> این پنلِ React همان API بک‌اند را صدا می‌زند، پس منطقِ صورتحساب، واترمارک و رد فیش دقیقاً همان قبلی و آزموده است.

بک‌اندِ فعلی (Node + Express + Socket.IO) که همهٔ منطقِ صورتحساب، واترمارک و صندوق را دارد **حفظ می‌شود**؛
این رابطِ React جای رابطِ قدیمی را می‌گیرد و به همان API وصل می‌شود. پس هیچ‌کدام از قابلیت‌هایی که قبلاً
ساختیم و تست شد (جمعِ صورتحساب، مهرِ ضدجعلِ رسید، رد فیش با حذف عکس، جداسازیِ درخواست‌ها) از دست نمی‌رود.
